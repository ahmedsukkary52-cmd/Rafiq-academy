- This TypeError is caught by the outer catch block, which sees `uid` is set → calls `auth.deleteUser(uid)` AGAIN → `deleted.length = 2`.

**Why `batch.commit()` might "succeed":** Unknown. `failingBatch.commit = async () => { throw new Error(...) }` should always throw. The batch is always created via `failingDb.batch()` → always returns `failingBatch`. No obvious bypass.

Async vs sync throw in a batch context behaves differently. The async version returns a rejected Promise; the synchronous version throws directly. If the calling code doesn't properly await the rejected Promise, the throw could be missed.
